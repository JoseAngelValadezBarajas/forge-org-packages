# @corefoundry-labs/forge-ui

Reusable React components for Forge-compatible products. The package exposes compiled ESM and TypeScript declarations from `dist`, with `@corefoundry-labs/forge-tokens` as an explicit runtime style dependency and React as a peer dependency.

```tsx
import { Button, FormField, Input } from '@corefoundry-labs/forge-ui';

<FormField label="Workspace name" hint="Shown to collaborators">
  <Input />
</FormField>;
<Button>Save</Button>;
```

`FeedbackStateV2` brings loading, empty, error, and read-only presentations under one additive API. The existing `EmptyState`, `ErrorState`, `LoadingState`, and `StatePanel` exports remain available with their current contracts.

```tsx
import { FeedbackStateV2, Button } from '@corefoundry-labs/forge-ui';

<FeedbackStateV2
  state="error"
  title="Could not load projects"
  description="Check your connection and retry."
  actions={<Button onClick={retry}>Retry</Button>}
/>
```

`FeedbackStateV2` reads the `--cf-v2-*` semantic roles when a dynamic theme is applied to an ancestor. Without a theme of your own, it uses the default Forge theme from `@corefoundry-labs/forge-tokens/theme-v2/tokens.css`. Apply a theme with `createTheme` and `applyTheme` from `@corefoundry-labs/forge-tokens/theme-v2`, or use CSS generated by `generateThemeCss`.

`ButtonV2` is the V2 action. It lives apart from V1 in `src/componentsV2` and uses only `--cf-v2-*` tokens, so it follows `ThemeScope` and `applyTheme` in light, dark, and high contrast. An icon-only button requires `aria-label`.

```tsx
import { ButtonV2 } from '@corefoundry-labs/forge-ui';
import { Plus, Search } from '@corefoundry-labs/forge-icons';

<ButtonV2 iconStart={<Plus />}>Add item</ButtonV2>;
<ButtonV2 variant="danger" size="sm" loading={saving} onClick={save}>Delete</ButtonV2>;
<ButtonV2 variant="ghost" aria-label="Search" iconStart={<Search />} />;
```

`TextInputV2`, `SelectV2`, `CheckboxV2`, and `SwitchV2` are the V2 form controls. Each one wraps a native element. `CheckboxV2` and `SwitchV2` take their label as children and require an accessible name without it.

```tsx
import { CheckboxV2, SelectV2, SwitchV2, TextInputV2 } from '@corefoundry-labs/forge-ui';

<TextInputV2 aria-label="Project name" size="md" value={name} onChange={rename} />;
<SelectV2 aria-label="Plan" value={plan} onChange={choose}>
  <option value="">Choose an option</option>
  <option value="team">Team</option>
</SelectV2>;
<CheckboxV2 checked={accepted} onChange={accept}>Accept terms</CheckboxV2>;
<SwitchV2 checked={enabled} onChange={toggle}>Notifications</SwitchV2>;
```

`CardV2`, `BadgeV2`, `TabsV2`, and `AlertV2` are the V2 display components. Only an interactive `CardV2` is an action, and `TabsV2` requires an accessible name.

```tsx
import { AlertV2, BadgeV2, CardV2, TabsV2 } from '@corefoundry-labs/forge-ui';

<CardV2 variant="outlined" header="Atlas" footer="Updated today">A home for your next idea.</CardV2>;
<CardV2 variant="interactive" header="Open Atlas" onClick={open} />;
<BadgeV2 tone="success" variant="subtle" size="md">Completed</BadgeV2>;
<TabsV2 aria-label="Project views" items={items} value={view} onValueChange={setView} />;
<AlertV2 tone="error" title="Could not save" description="Try again." onDismiss={close} />;
```

`DialogV2`, `TooltipV2`, `PopoverV2`, and `DropdownMenuV2` are the V2 overlays. They render in place and rise into the browser top layer, so they inherit their `ThemeScope` and no ancestor can clip them. They need the Popover API: Chrome and Edge 114, Safari 17, or Firefox 125.

```tsx
import { ButtonV2, DialogV2, DropdownMenuV2, PopoverV2, TooltipV2 } from '@corefoundry-labs/forge-ui';

<DialogV2 open={open} onOpenChange={setOpen} title="Confirm action" footer={<ButtonV2 onClick={confirm}>Continue</ButtonV2>} />;
<TooltipV2 content="Copy the link"><ButtonV2 aria-label="Copy" iconStart={<Copy />} /></TooltipV2>;
<PopoverV2 trigger={<ButtonV2>More options</ButtonV2>} title="Preferences">{content}</PopoverV2>;
<DropdownMenuV2 trigger={<ButtonV2>More actions</ButtonV2>} items={[{ id: 'edit', label: 'Edit', onSelect: edit }]} />;
```

`ProgressV2`, `SkeletonV2`, `SnackbarV2`, and `AvatarV2` cover loading, transient feedback, and identity. A snackbar never takes focus, and the parent owns the list.

```tsx
import { AvatarV2, ProgressV2, SkeletonV2, SnackbarStackV2, SnackbarV2 } from '@corefoundry-labs/forge-ui';

<ProgressV2 label="Uploading" value={68} />;
<SkeletonV2 shape="rectangle" size="md" animation="pulse" />;
<SnackbarStackV2>
  {items.map((item) => <SnackbarV2 key={item.id} tone="success" title={item.title} onDismiss={() => remove(item.id)} />)}
</SnackbarStackV2>;
<AvatarV2 alt="Ada Lovelace" src={photo} initials="AL" size="lg" />;
```

Preview the V2 components, the V1 components, and `FeedbackStateV2` locally with `npm run playground:ui` from the repository root. The host lets you change the preset, mode, and primary seed within the preview. The preview documents package rendering; it is not a human Figma certification.

Build and test this package independently from the repository root with `npm run build --workspace=@corefoundry-labs/forge-ui` and `npm test --workspace=@corefoundry-labs/forge-ui`.

Consumers can import the safe aggregate stylesheet from `@corefoundry-labs/forge-ui/styles.css`. It contains
only package-global CSS and a layer declaration; component styles remain CSS Modules emitted
beside each compiled component, so selectors such as `.button` do not leak into the consumer's
global stylesheet. Bundlers must support CSS imports and CSS Modules (for example Vite, webpack,
or Next.js). The package's ESM entry is suitable for client bundlers; SSR applications should
use their bundler's CSS extraction/manifest mechanism and must not execute the ESM entry directly
in a CSS-unaware Node runtime.
